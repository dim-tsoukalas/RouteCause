4.3. UPDATE Message Format
An UPDATE message is used to transfer routing information between BGP peers.
An UPDATE message advertises feasible routes that share common path attributes
to a peer, or withdraws multiple unfeasible routes from service. An UPDATE
message can advertise at most one set of path attributes, but multiple
destinations. Withdrawn Routes carry the IP address prefixes that are being
withdrawn from service because they are no longer deemed reachable.

5.1.2. AS_PATH
AS_PATH is a well-known mandatory attribute composed of a sequence of AS path
segments. It identifies the autonomous systems through which routing
information carried in the UPDATE message has passed. When a BGP speaker
propagates a route to an external peer, it prepends its own AS number to the
AS_PATH. The AS_PATH attribute is used in route selection and, critically, in
loop detection.

9.1.2. Route Selection and Loop Detection
If the AS_PATH attribute of a BGP route contains an autonomous system loop,
the route SHOULD be excluded from the Phase 2 decision function. An AS loop is
detected when the local system's own autonomous system number appears in the
AS_PATH attribute of a received route. Such routes are not installed and are
not propagated, which prevents persistent routing loops from forming through
the AS_PATH mechanism.

9.2. Update-Send Process
The Update-Send process is responsible for advertising UPDATE messages to peers.
When a route becomes unfeasible, the speaker withdraws it by including its
prefix in the Withdrawn Routes field of an UPDATE message. Repeated
announcement and withdrawal of the same prefix (route flap) imposes churn on
peers and may be subject to damping.
